# Manhattan — Three.js runtime

The browser runtime for the procedural Manhattan world. Blender authors the
content; this renders it.

**Status: v0.1.** It streams the whole island, carries building identity into
the browser, and you can walk and fly through it. It is not a game yet — no
vehicles, no pedestrians, no interiors, one LOD.

## Run it

```bash
npm --prefix apps/manhattan-threejs install
```

```bash
npm --prefix apps/manhattan-threejs run dev
```

Then open <http://localhost:5173>.

The world data is served straight out of the repo by a small Vite middleware —
nothing is copied into `public/`:

| URL | Serves |
|---|---|
| `/tiles/*` | `exports/` — 118 Draco-compressed glb tiles, 26.3 MB |
| `/data/*` | `data/manhattan/runtime/` — `city.json`, `core.bin`, `text.json`, 2.8 MB |
| `/draco/*` | `public/draco/` — decoder copied from the local `three` package |

If `/data/` 404s, build the payload first:

```bash
python scripts/phase2/45_build_runtime_data.py
```

## Controls

| Key | Action |
|---|---|
| `W A S D` | move |
| `Space` / `C` | up / down in fly, jump in walk |
| `Shift` | boost |
| `F` | toggle fly ↔ walk |
| `E` | ride a lift at a link threshold (Phase 3B: a ride, not a teleport) |
| click canvas | capture the pointer to look; `Esc` releases |
| click a building | inspect it |
| `H` | hide the help line |

## How it fits together

```
src/main.js       boot, render loop, picking, HUD
src/city.js       loads city.json + core.bin + text.json, typed accessors
src/streamer.js   distance-prioritised tile load/unload
src/controls.js   pointer-lock fly and walk, raycast collision
src/sky.js        sky, sun, fog, per-mode clip planes
src/doors.js      Phase 3B: real doorways, walk-in interiors, lift rides
```

### Doorways (Phase 3B)

The corridor buildings get real openings, cut into the baked tile walls at
street level and punched through the interiors' glazed walls. The walk
collider probes the actual tile meshes, so a hole in the mesh is a hole in
the collision: no keypress and no teleport to enter — you walk in, and
walking back out reverses it. Data-driven off `data/manhattan/doors/
doors.json` (generated by `scripts/phase2/68_build_doors.py`). See
`docs/phase2/PHASE3B.md`.

### Building identity

Every building carries its `building_id` from the registry all the way to the
browser:

```
registry CSV  ->  Blender attribute "_bid"  ->  glTF _BID accessor
              ->  geometry.attributes._bid  ->  city.get(id)
```

Clicking a building reads `_bid` off the hit face and looks the record up in
`core.bin`. That is the regression this whole chain exists to protect: the
glTF exporter drops custom attributes unless `export_attributes=True`, and
without `_BID` there is no way to know what you clicked.

### Coordinates

The world is a local tangent plane centred on 40.78 N, 73.968 W, in metres.
Blender is Z-up and glTF is Y-up, so the exporter maps
`(x, y, z)_blender → (x, z, −y)_gltf`. In the browser:

```
world.x =  x_m        world.y = height        world.z = −y_m
```

`city.js` exports `toWorld` / `fromWorld` so this conversion lives in one
place.

### Clip planes

Depth precision is the constraint at 22 km. A 24-bit depth buffer stretched
from a 0.25 m near plane to 45 km produces visible banding across the ground —
Phase 1 lost three attempts to this before measuring it. The two camera modes
therefore get different ranges: walk uses 0.25 m – 14 km, fly uses 12 m – 45 km.

## Measured

Boot on a local dev server, camera over Midtown, all 118 tiles resident:

| | |
|---|---|
| buildings | 56,476 |
| tiles | 118 / 118 resident, 26.3 MB |
| triangles loaded | 3.92 M |
| triangles rendered | 1.57 M after frustum culling |
| draw calls | 79 – 211 depending on view |
| runtime payload | 2.76 MB (`city.json` 0.01, `core.bin` 1.13, `text.json` 1.62) |

The cell grid in `docs/phase2/CELL_REPORT.json` projects a worst-case resident
budget of 2.04 M triangles once the five-LOD ladder is authored, with no
frustum culling applied. The current single-LOD build already sits inside that.

## Known limitations

- **One LOD.** `44_build_cells.py` defines the five-tier ladder and the 200 m
  cell grid, but the per-LOD sector meshes are not exported yet. `FAR` in
  `streamer.js` is therefore set wide enough to cover the island so the skyline
  is complete.
- **No vehicles, pedestrians, interiors or audio.** Phases 2F–2J.
- **Walk collision is raycast-based.** Accurate against walls and ground,
  but it has no capsule sweep, so a fast run into a corner can jitter.
- **Facades are flat colour.** Per-building colour arrives in `COLOR_0`;
  the procedural facade generation is Phase 2D proper.
